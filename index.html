这套系统的设计原则

01 · 先记录，再分析

首页让记录在一两次点击内完成。趋势后置，避免数据面板抢走注意力。

02 · 让行动有即时反馈

每一档都有即时计数、轻量动效和撤销入口，建立“点一下就有进展”的感觉。

03 · 不把自律变成惩罚

吸烟次数与抵抗次数一起记录；允许漏记、低状态和重新开始。

Token 应该怎样设置？

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens。只需授予 Gists: Read and write。不要把 Token 发到聊天里，也不要放进 HTML 文件。

「检测连接」只检查读取权限；首次同步时才会验证写入权限。数据先用浏览器内的 AES-GCM 加密，再上传到 Gist。加密口令忘记后无法恢复云端数据。

SYNC RULES

同步规则

01
先加密，再上传

记录文本、财务数据、习惯与私密周末记录都在加密范围内。

02
冲突时暂停，不静默覆盖

如果云端和本机都在上次同步后发生变化，会要求你主动选择恢复还是覆盖。

03
跨设备要用相同口令

在另一台设备打开同一 V7 文件，输入 Token 和同一个加密口令，再点击「从云端恢复」。

04
Gist 并不是私人保险箱

Secret Gist 仅是不公开列出；任何拿到链接的人都可能访问。因此只上传加密后的密文。

本地自动保存仍然生效。云同步由你控制；Token 与加密口令不会写入导出的 HTML 源码。
